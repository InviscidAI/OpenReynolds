# What is in here

Small scripts and some notes, refreshed from the distribution at the start of every
session. They are offered, not imposed: use them, edit them, replace them, or ignore
them. Nothing checks whether you did.

Each takes `--help`.

| | |
|---|---|
| `geometry_view.py` | Surfaces (`.stl`, `.obj`, `.ply`, `.vtk`, and `.step`/`.iges` tessellated coarsely for the picture and thrown away afterwards) drawn from four fixed views with every facet edge and the bounding-box ticks on, plus open edges, non-manifold edges, connected bodies, extents and face-area range. No verdicts: whether 40 open edges matter depends on where they are. |
| `cad_convert.py` | STEP and IGES to STL. gmsh here is built against OpenCASCADE, so a `.step` is read as B-rep -- exact circles, declared units, real trimmed surfaces -- and `import gmsh` will answer questions about it directly, which is the intended way to decide the tessellation. This script decides nothing: you pass `--clmax` and it converts, then reports the unit it read or was given, the entity counts, the tightest curve it found and the sagitta that implies, the facet count and longest edge that came out, and the gmsh calls in order. It refuses twice, both times where a wrong answer looks right: no `--clmax`, and a file that declares no unit with no `--unit`. |
| `mesh_look.py` | A mesh looked at and measured in one call, straight from `constant/polyMesh` -- no solve, no fields, no time directory. One PNG: the boundary with **one colour per patch** (2D gets the patches and the cells; 3D gets the patches and a cut on each axis), and under it the table -- cells, faces, points, the bounding box, whether it is one cell thick, and for every patch its type, face count, area, centre and mean unit normal, which is what tells an inlet from an outlet without guessing from where it sits. The cell zones and face zones in `constant/polyMesh` are listed under the patches -- name and count either format, and a cell zone's centroid and the box its cell centres span where the file is ascii -- because a sliding interface, a frozen rotor and an overset region are all named against a zone, and a dictionary naming a zone the mesh does not have fails at the first solver step. A mesh with no zone files says so rather than saying nothing. `checkMesh` runs with it and its verdict and the three metrics a solver minds are in the same report. `--json` writes the same facts for a script to read. |
| `disk.py` | What is filling the workspace, and what of it is safe to delete. There is one disk: an account is capped at one instance, a new study joins the existing one, and every study ever run is a sibling directory under `/work` sharing a single 20 GB quota. So a 24 MB case can be refused because an animation run three weeks ago left 3 GB of frames next door -- measured 2026-09-08 at 30.8 GB used, of which 24.5 GB was regenerable scratch nothing was responsible for clearing. `report` ranks every directory by size and says how much of each could be produced again. `prune` removes only that -- `processor*`, solution times other than the latest, `VTK/`, animation frames -- and never `0/`, `constant/`, `system/`, `log.*`, `postProcessing/`, figures, reports or `Allrun`/`Allmesh`/`build.py`, and never a time directory that carries a `polyMesh` of its own, which on a moving mesh is the only record the run keeps of its own motion. It is a dry run unless `--apply`, it refuses to guess which study to prune, and it never deletes a whole study: removing one is a person's decision and this exists to make that unnecessary. |
| `mesh_digest.py` | `checkMesh` output as a metric table — the numbers and the patch table, no thresholds applied. |
| `cells_estimate.py` | Cell count predicted from the STL and the snappy dictionaries, before the build rather than after it. |
| `log_digest.py` | Solver log to a residual plot, a last-iteration table, and the continuity and bounding summary. |
| `reattach.py` | Where the flow leaves a wall and where it comes back, off the wall shear: the sign changes along a patch, with the primary reattachment picked out of them as the downstream end of the longest reversed-flow run -- not the first sign change, which on a backward-facing step is the corner eddy, and not the last, which is a secondary bubble. That rule is stated in the report wherever it actually chose between two bubbles, because on a geometry whose downstream separation is the longer one it names that instead. Both of those are printed beside the answer, so a number computed another way can be checked against the same list rather than merely disagreed with. Which sign of tau means attached is measured off `U` (tau tracks the near-wall velocity along a wall; the domain mean says which way downstream is), so no convention has to be known or got right. It reports the local face spacing with the number and rounds the answer to it. It never asserts a length unit it cannot read: with a `--height` other than 1 the answer is in step heights and says `h`; without one -- and `--height 1` is without one, since 1.0 is the flag's default and nothing here can tell an explicit 1 from an unused flag -- it is in whatever the wall's coordinate was and the label is left empty; `--units h` says it by hand, which is also the only way to label a table already sampled in x/h. A label invented here is a comparison switched off in `claims.py`. `--from-file` runs a sampled `.raw` or any two-column table through the same arithmetic; `--plot` draws the curve and the figure carries the number it was drawn from. |
| `claims.py` | The number a figure was drawn from, stamped into the PNG itself, so the picture and the prose can be put side by side. `attach` stamps a figure -- including one a hand-written script drew -- `read` prints what one carries, and `check` reports two claims about the same quantity that disagree, and any claim the written answer contradicts or never quotes. It exists because a study delivered a figure annotated 7.57 with an answer that said 6.4 and reconciled neither; the caption drawn on a figure and the value stamped into it come from one call, so those two at least cannot drift. It exits non-zero on a disagreement -- as `preflight.py` does on a failing finding, and unlike the scripts here that only ever report -- because what it reports is arithmetic rather than judgement. Two claims whose unit labels differ are not compared, since guessing a conversion is how a reconciliation tool starts inventing its own errors, and they are printed as not compared rather than skipped: the all-clear is never shown over a pair nothing checked. |
| `render.py` | Fixed pyvista scenes for a case: mesh cuts and field slices, as PNGs, with cameras that do not move between runs so two of them are a visual diff. `--fields` takes solver outputs and also `vorticity` (signed, out-of-plane) and `Q`, which it computes from `U` rather than leaving to a hand-written script. |
| `case_gen.py` | The case files for a mesh that already exists: `0/`, `system/` and `constant/`, sized to the mesh in front of it. It reads the patch names and types out of `constant/polyMesh/boundary`, the cell count, bounding box and smallest cell out of `checkMesh`, and each patch's area, centre and normal out of `mesh_look.py` -- and from those works out which way the inlet flows (its own normal, pointed at the middle of the domain, which is why a U-duct with both ends on the left comes out right), the hydraulic diameter the Reynolds number is on, and whether this is a body in open flow or a passage (a wall patch that is not part of the domain's own bounding box is a body), which sets the free-stream turbulence. Every patch gets a role -- inlet, outlet, wall, slip, symmetry, a belt that moves with the stream, a wheel that spins, empty -- from what you name, then from the mesh's own constraint types, then from the name; and a `boundaryField` entry in every field the turbulence model reads. Give it `--reynolds` and it solves for the viscosity and says so. It builds no geometry: that is the `mesh` tool's job. |
| `preflight.py` | The cheap questions asked before an expensive run -- patch names against the fields, `empty` treatment on a 2D case, STL scale, Re against nu, predicted cells, checkMesh, a one-iteration probe, Courant and disk -- each answered as a finding with what was measured, what it means, and a repair you may or may not want. |
| `ladder.py` | A ladder of reduced cases for this case, read out of the case itself: the class it appears to be and the evidence for that reading, then the rungs in order -- what each one adds, what to measure on it, the answer that is already known and where it comes from, what counts as passing, and what it costs. The rule is that a rung's answer never comes from another solve: Archimedes, the ITTC-57 line, Kelvin's 19.47 degrees, Hagen-Poiseuille, the divergence theorem. `--rung n` prints one in full with the dictionary edits that would build it. `--record n --status pass\|fail\|skipped --value X` writes a rung's outcome to the study manifest on the volume, where the report's evidence column and `progress_report.py` read it back -- in this session or the next. It edits no case and runs nothing, the exit code is always 0, and climbing none of the rungs is a legitimate choice. |
| `locate.py` | Where a diverging run went wrong, measured off the case rather than argued: the last written fields with min, max, mean and the extremum's cell, coordinates, owning patch and distance to the domain boundary, ascii or binary mesh alike; the solver log read for the field whose residual or bounding warning degrades first and when, with the Courant tail; and `--compare <other-case>` running the same scan on a second mesh of the same problem, because a value that does not move when the mesh changes is set by the boundary specification, not the grid. It reports in preflight's measured/means/repair register, offers no mechanism -- location over explanation is its whole idea -- edits nothing, and exits 0 whatever it finds. |
| `hisa_env.py` | Where HiSA -- the implicit density-based shock-capturing solver -- is on this instance: baked into the image (newer images, no exports needed), built onto the volume (older images), or absent. Says present, absent, or present-with-unresolved-libraries; for a volume build prints the four export lines a shell needs and the `-x` forwarding `mpirun` needs; prints the path to the ONERA M6 case HiSA ships, which is the shortest route to a correct dictionary set. `--json` for reading it from another script. |
| `layer_report.py` | How much of a wall actually carries a prism layer, measured off the mesh rather than taken from the mesher: the first-cell height at every patch face, `2 \|C_face - C_owner\|`, computed from `points`, `faces` and `owner` so nothing has to have been written and no solver has to have run. Coverage is that height against a reference wall spacing -- the same wall meshed with no layer request (`--ref`), or a spacing you already know (`--wall-spacing`); with neither, the threshold comes from the mesh itself and says so. It exists because snappyHexMesh reports a layer table, cfMesh reports nothing comparable, and the three claims about one hull could not be put next to each other until the meshes were measured with one metric. `--json` for reading it from another script. |
| `cfmesh.py` | The other mesher on this image, and the four traps between you and it. snappyHexMesh's layer stage is a loop that inserts prisms and then deletes them where a quality metric fails -- on one hull it reached 88.6% coverage on its first iteration and eroded to 66.7% by its fiftieth, then printed 66.7% and exited 0; cfMesh's `cartesianMesh` extrudes a sheet and optimises afterwards, so nothing can un-extrude a face, and it covered 100.0% of the same wall. It is prebuilt in the image, needs no build, no volume and no exports, and was available and unused for four rounds. `where` says whether that is still true of the image you are on: it probes eight binaries -- the four meshers, `generateBoundaryLayers`, and three more it runs itself (`surfaceFeatureEdges` and `surfaceToFMS`, which the record files under surface prep, and `improveSymmetryPlanes`, which it files under mesh tools) -- and names the three boundary-layer classes that never were executables, so a session does not conclude the install is broken. (The image ships 25 in all; the other seventeen are listed in `qa-runs/comp/cfmesh/README.md` and this does not go looking for them -- including `surfaceGenerateBoundingBox`, which is left out on purpose because it is trap 2 and `box` replaces it.) `box` writes a body and its domain box as one closed multi-solid STL, refusing a body that pokes through the box and naming the faces it merely touches, because those are cut planes. `case` writes a `meshDict` whose keys and whose `surfaceFile` decide each other: `surfaceFeatureEdges` indexes every solid name, so against the `.ftr` it writes the key must be the regex `"hull_.*"` and a literal matches nothing -- warned once on the mesh side and *nothing at all* on the surface side, then meshed with no refinement and no layers at exit 0 -- while against a raw STL the solid names arrive verbatim and the literal is the right key, which is how cfMesh's own tutorials are written. It refuses the requests cfMesh accepts and quietly drops (one layer on a patch, a thickness ratio under 1, and type `symmetryPlane` wherever a type can be asked for -- `--patch NAME:TYPE`, `--default-type`, and `meshdict()`'s `wall_type`; `--wall` takes a name and not a type). It also says what `renameBoundary` merges: a `defaultName` that is present makes cfMesh fold every unnamed solid into ONE patch -- added only where a solid is in fact left over, so naming all of them leaves no `farField` at all -- and `--wall hull` alone gives a two-patch mesh with all six box faces in `farField` and no inlet to name -- `--patch xMin:patch` and `--symmetry yMin` are how faces are kept apart. `prepare` is the two edits that make an existing snappy mesh readable, in the order that works. `check` reads back what the mesh got: whether the wall kept its name, whether the wall's own face size is nearer the `cellSize` the `localRefinement` key that names THIS wall asked for or the floor it falls back to without it (`boundaryCellSize` where the dictionary sets one, `maxCellSize` otherwise) -- and where no key names the wall, or the two sizes are less than one octree halving apart, it says it cannot tell rather than guessing, and the coverage number from `layer_report.py`. What it cannot do is printed where the choice is made: cfMesh sizes the layer stack from the local cell, so there is no y+ to ask for, only one to measure afterwards. |
| `gallery.py` | The manifest turned into a self-contained `gallery.html`, a contact sheet, and a list of the latest artifact of each kind. Images are embedded, so the page is the same page on a laptop that has never seen `/work`. |
| `first_look.py` | A meshed but unrun case as one contact sheet: geometry, the whole mesh, a close-up on whatever it was refined around, the named patches, and the counts. Panels that fail print their error in place rather than taking the sheet down, and one `read_file` on the result is the state of the case before a core-hour is spent. |
| `progress_report.py` | Phase, the time reached, the pace, and the exact paths of the pictures that already exist — one answer to "what is happening?" assembled from the case rather than from a log tail. Ladder rung outcomes recorded on the volume surface here too, so a fresh session sees what an earlier one established. |
| `results.py` | A finished case as the standard set of pictures and plots in one call, rather than a render command per view. |
| `study_run.py` | Drives a study through its phases and picks up where the last session stopped, reading the phase table `study_state.py` leaves on the Volume. |
| `study_state.py` | Two files under `<study>/.reynolds/`: a manifest of what has been produced and what each artifact is for, and a phase table saying how far the study got. Both are plain text on the Volume, so a session that ends mid-solve leaves an answer behind for the next one. `digest` reads all of it in one call -- the cases present, whether each is meshed and its cell count, the latest time written, the phase statuses and the artifact tally -- so orienting on resume is a single read rather than a walk of the directory. |
| `showcase.py` | The same case drawn to be shown rather than checked: a Q-criterion vortex isosurface, streamtubes seeded across the inflow, the body under its own pressure field, or a styled slice -- dark ground, lit surfaces, a colour map per quantity. `--orbit N` swings the camera round and `--sweep N` walks a plane through the domain, both of which work on a steady solution; the frames land in a `*_frames/` directory and are encoded on your machine like any other animation. |
| `animate.py` | One PNG per write time into a `*_frames/` directory, fixed camera. Designed to run as a job and to flush each frame as it lands, so the frames mirror home while they render and the harness assembles the gif on your machine — including a partial one from the frames so far. |
| `encode.py` | A `*_frames/` directory turned into a `.gif`, `.mp4` or `.webp` on the instance, reading the frame order and rate from the `frames.json` sidecar `animate.py`/`showcase.py` leave. The image carries the encoder (imageio with ffmpeg), so the finished animation can be made here rather than only on your machine — which is the only place a hosted session has. |
| `scratch.py` | The case directory lives on the Volume, which is a network filesystem, so the stages that touch many small files pay for every one across the wire — `reconstructPar` most of all (measured 5m23s on the Volume against 27s on local disk for one 160-write case, 39s against 4s for 40 writes; the solver itself about 20% slower). `run` stages a case to container-local `/tmp`, runs a command there, and copies results back to the Volume every minute, so the durable copy is never more than a checkpoint behind and a preempted run resumes from `latestTime` with nothing lost. `reconstruct` does the same for reconstruction, off the decomposed data already on the Volume, so a lost reconstruct never costs the solve — and it is scoped (`--latest`, `--time A:B`, `--fields "U p"`) and idempotent (only the times a case is missing, so a second call is nearly free). Uses only `rsync` and the OpenFOAM tools already here. |
| `templates/duct2d.py` | A closed planar outline meshed in quads (`Mesh.Algorithm 8`, Blossom full-quad recombination, `setRecombine`), extruded one cell into hexahedra (`extrude(..., numElements=[1], recombine=True)`), converted with `gmshToFoam`, the walls and the two z faces retyped `wall`/`empty` with `foamDictionary`, `checkMesh`, `mesh_look.py`. Copy it into a case directory, edit `LENGTH_M` and `HEIGHT_M`, run it -- the working 2D recipe, not a page describing one. |
| `templates/body_in_box.py` | An OpenCASCADE primitive cut out of a flow box (`gmsh.model.occ`, a boolean, not a bounding-box guess) and meshed body-fitted with tetrahedra -- no STL, no snappyHexMesh -- converted with `gmshToFoam`, the body retyped `wall`, `checkMesh`, `mesh_look.py`. Copy it in, edit `BODY_RADIUS_M` and `CELL_SIZE_M`, run it -- the working 3D recipe, including how the box around the body is sized and its faces named. |

Anything that writes a PNG is worth knowing about twice over, because `read_file` on an
image path hands the picture back to you rather than its bytes — so a render is
something you can look at, not only something you can produce.

`ENVIRONMENT.md` lists what is installed on this instance — the Python packages, the
binaries on PATH, and which tool does a job (PDF is `pdftoppm`, not `fitz`; gifs are
`imageio`; meshing is `gmsh`) — so the environment can be read rather than probed, and the
sealed network is stated once rather than met as a surprise.

`templates/` holds the two meshing recipes as working scripts rather than as prose to
retype: `duct2d.py` for a plane case and `body_in_box.py` for a body in a flow box, each
copy-edit-run, each ending in `checkMesh` and a `mesh_look.py` call.

`notes/openfoam-field-notes.md` is OpenFOAM practice written as field notes rather than
procedure. `notes/bundle-layout.md` is one suggested `/work` layout, labelled a
suggestion. `notes/openfoam-agent-architecture.md` is a longer design document, optional
reading.
