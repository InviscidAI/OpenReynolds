# What is in here

Small scripts and some notes, refreshed from the distribution at the start of every
session. They are offered, not imposed: use them, edit them, replace them, or ignore
them. Nothing checks whether you did.

Each takes `--help`.

| | |
|---|---|
| `geometry_view.py` | Surfaces (`.stl`, `.obj`, `.ply`, `.vtk`) drawn from four fixed views with every facet edge and the bounding-box ticks on, plus open edges, non-manifold edges, connected bodies, extents and face-area range. No verdicts: whether 40 open edges matter depends on where they are. |
| `mesh_digest.py` | `checkMesh` output as a metric table — the numbers and the patch table, no thresholds applied. |
| `cells_estimate.py` | Cell count predicted from the STL and the snappy dictionaries, before the build rather than after it. |
| `log_digest.py` | Solver log to a residual plot, a last-iteration table, and the continuity and bounding summary. |
| `render.py` | Fixed pyvista scenes for a case: mesh cuts and field slices, as PNGs, with cameras that do not move between runs so two of them are a visual diff. |
| `case_gen.py` | Runnable cases from a template name and a few numbers -- 2D external flow (circle, square, L, vehicle, an imported profile), Y/T/Z/F/M ducts, sharp, mitred and rounded bends; mesh-only, steady or transient; moving ground and rotating wheels. Every file it writes is one you can open and edit. |
| `snappy_gen.py` | The same idea as `case_gen.py` for a surface you uploaded: a background box, snappyHexMesh cut to your STL, boundary layers sized to a y+ you name, and the dictionaries for a steady, transient, thermal or MRF run. The reference area is measured off the STL rather than typed in, and a `--symmetry` plane scales it in the same place it cuts the mesh -- halving for a plane through the body, not halving for one that only bounds the flow. `--rotate y:90` points a body that was not exported facing the flow at it, and an MRF case objects when the axis it was given is not the body's own. `Allmesh` meshes the whole thing in one call. |
| `preflight.py` | The cheap questions asked before an expensive run -- patch names against the fields, `empty` treatment on a 2D case, STL scale, Re against nu, predicted cells, checkMesh, a one-iteration probe, Courant and disk -- each answered as a finding with what was measured, what it means, and a repair you may or may not want. |
| `ladder.py` | A ladder of reduced cases for this case, read out of the case itself: the class it appears to be and the evidence for that reading, then the rungs in order -- what each one adds, what to measure on it, the answer that is already known and where it comes from, what counts as passing, and what it costs. The rule is that a rung's answer never comes from another solve: Archimedes, the ITTC-57 line, Kelvin's 19.47 degrees, Hagen-Poiseuille, the divergence theorem. `--rung n` prints one in full with the dictionary edits that would build it. `--record n --status pass\|fail\|skipped --value X` writes a rung's outcome to the study manifest on the volume, where the report's evidence column and `progress_report.py` read it back -- in this session or the next. It edits no case and runs nothing, the exit code is always 0, and climbing none of the rungs is a legitimate choice. |
| `locate.py` | Where a diverging run went wrong, measured off the case rather than argued: the last written fields with min, max, mean and the extremum's cell, coordinates, owning patch and distance to the domain boundary, ascii or binary mesh alike; the solver log read for the field whose residual or bounding warning degrades first and when, with the Courant tail; and `--compare <other-case>` running the same scan on a second mesh of the same problem, because a value that does not move when the mesh changes is set by the boundary specification, not the grid. It reports in preflight's measured/means/repair register, offers no mechanism -- location over explanation is its whole idea -- edits nothing, and exits 0 whatever it finds. |
| `hisa_env.py` | Where HiSA -- the implicit density-based shock-capturing solver -- is on this instance: baked into the image (newer images, no exports needed), built onto the volume (older images), or absent. Says present, absent, or present-with-unresolved-libraries; for a volume build prints the four export lines a shell needs and the `-x` forwarding `mpirun` needs; prints the path to the ONERA M6 case HiSA ships, which is the shortest route to a correct dictionary set. `--json` for reading it from another script. |
| `layer_report.py` | How much of a wall actually carries a prism layer, measured off the mesh rather than taken from the mesher: the first-cell height at every patch face, `2 \|C_face - C_owner\|`, computed from `points`, `faces` and `owner` so nothing has to have been written and no solver has to have run. Coverage is that height against a reference wall spacing -- the same wall meshed with no layer request (`--ref`), or a spacing you already know (`--wall-spacing`); with neither, the threshold comes from the mesh itself and says so. It exists because snappyHexMesh reports a layer table, cfMesh reports nothing comparable, and the three claims about one hull could not be put next to each other until the meshes were measured with one metric. `--json` for reading it from another script. |
| `gallery.py` | The manifest turned into a self-contained `gallery.html`, a contact sheet, and a list of the latest artifact of each kind. Images are embedded, so the page is the same page on a laptop that has never seen `/work`. |
| `first_look.py` | A meshed but unrun case as one contact sheet: geometry, the whole mesh, a close-up on whatever it was refined around, the named patches, and the counts. Panels that fail print their error in place rather than taking the sheet down, and one `read_file` on the result is the state of the case before a core-hour is spent. |
| `progress_report.py` | Phase, the time reached, the pace, and the exact paths of the pictures that already exist — one answer to "what is happening?" assembled from the case rather than from a log tail. Ladder rung outcomes recorded on the volume surface here too, so a fresh session sees what an earlier one established. |
| `results.py` | A finished case as the standard set of pictures and plots in one call, rather than a render command per view. |
| `study_run.py` | Drives a study through its phases and picks up where the last session stopped, reading the phase table `study_state.py` leaves on the Volume. |
| `study_state.py` | Two files under `<study>/.reynolds/`: a manifest of what has been produced and what each artifact is for, and a phase table saying how far the study got. Both are plain text on the Volume, so a session that ends mid-solve leaves an answer behind for the next one. |
| `corpus.py` | The tutorials and your finished studies turned into indexes you can query, and the dictionary reader that builds them. `build` writes one JSON row per tutorial case and one per study — solver, whether it solves or only meshes, turbulence, how the mesh is built, the boundary types per field — plus, for a study, how far it got, what it produced and what its ladder rungs measured against their known answers. 556 tutorials in under a second. The two tiers are separate files and every row says which it is, because a tutorial is a demonstration and a past study is your own output, and neither is evidence that the other is right; no row carries a reference value. `read` prints one dictionary's entries and `--key` picks a single one out, `boundaries` prints a field file's patches and their BC types, and anything unreadable comes back null rather than guessed. |
| `search.py` | The corpus asked a question: `regime` for ranked cases to seed from, `keyword` for what the corpus actually sets a scheme to, `failure` for studies that hit something like this before. Every hit says which tier it came from and why it matched — an exact match on an indexed field outranks the same word turning up in a path, and both are printed, along with the words it could not match and how big the tie was. A value distribution also says how many tutorial families hold each value, because five cases from one directory of siblings and five unrelated ones are different claims the counts alone cannot tell apart. Every query is written to `retrievals.jsonl` with its whole ranked list, the passed-over hits included; `took <path>` records what you actually used, against the query that offered it, and `log` reads it all back. Nothing infers what was taken — a query that returned one case is not a case adopted. It rebuilds the index when it is missing or was built against a different OpenFOAM. |
| `showcase.py` | The same case drawn to be shown rather than checked: a Q-criterion vortex isosurface, streamtubes seeded across the inflow, the body under its own pressure field, or a styled slice -- dark ground, lit surfaces, a colour map per quantity. `--orbit N` swings the camera round and `--sweep N` walks a plane through the domain, both of which work on a steady solution; the frames land in a `*_frames/` directory and are encoded on your machine like any other animation. |
| `animate.py` | One PNG per write time into a `*_frames/` directory, fixed camera. Designed to run as a job and to flush each frame as it lands, so the frames mirror home while they render and the harness assembles the gif on your machine — including a partial one from the frames so far. |

Anything that writes a PNG is worth knowing about twice over, because `read_file` on an
image path hands the picture back to you rather than its bytes — so a render is
something you can look at, not only something you can produce.

`notes/openfoam-field-notes.md` is OpenFOAM practice written as field notes rather than
procedure. `notes/bundle-layout.md` is one suggested `/work` layout, labelled a
suggestion. `notes/openfoam-agent-architecture.md` is a longer design document, optional
reading.
