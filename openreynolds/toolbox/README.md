# What is in here

Small scripts and some notes, refreshed from the distribution at the start of every
session. They are offered, not imposed: use them, edit them, replace them, or ignore
them. Nothing checks whether you did.

Each takes `--help`.

| | |
|---|---|
| `geometry_view.py` | Surfaces (`.stl`, `.obj`, `.ply`, `.vtk`, and `.step`/`.iges` tessellated coarsely for the picture and thrown away afterwards) drawn from four fixed views with every facet edge and the bounding-box ticks on, plus open edges, non-manifold edges, connected bodies, extents and face-area range. No verdicts: whether 40 open edges matter depends on where they are. |
| `cad_convert.py` | STEP, IGES and BREP to STL. gmsh here is built against OpenCASCADE, so a `.step` or `.brep` is read as B-rep -- exact circles, declared units, real trimmed surfaces -- and `import gmsh` will answer questions about it directly, which is the intended way to decide the tessellation. This script decides nothing: you pass `--clmax` and it converts, then reports the unit it read or was given, the entity counts, the tightest curve it found and the sagitta that implies, the facet count and longest edge that came out, and the gmsh calls in order. It refuses twice, both times where a wrong answer looks right: no `--clmax`, and a file that declares no unit with no `--unit` -- which is every `.brep`, since OpenCASCADE serialises raw coordinates and the unit stays with whatever wrote them. |
| `mesh_look.py` | A mesh looked at and measured in one call, straight from `constant/polyMesh` -- no solve, no fields, no time directory. One PNG: the boundary with **one colour per patch** (2D gets the patches and the cells; 3D gets the patches and a cut on each axis), and under it the table -- cells, faces, points, the bounding box, whether it is one cell thick, and for every patch its type, face count, area, centre and mean unit normal, which is what tells an inlet from an outlet without guessing from where it sits. The cell zones and face zones in `constant/polyMesh` are listed under the patches -- name and count either format, and a cell zone's centroid and the box its cell centres span where the file is ascii -- because a sliding interface, a frozen rotor and an overset region are all named against a zone, and a dictionary naming a zone the mesh does not have fails at the first solver step. A mesh with no zone files says so rather than saying nothing. `checkMesh` runs with it and its verdict and the three metrics a solver minds are in the same report. `--json` writes the same facts for a script to read. `--out` and `--json` are relative to where you run it from, like every other script here (not to the case); without `--out` the picture is `<case>/look.png`, and the report's `picture:` line is the absolute path written. |
| `disk.py` | What is filling the workspace, and what of it is safe to delete. There is one disk: an account is capped at one instance, a new study joins the existing one, and every study ever run is a sibling directory under `/work` sharing a single 20 GB quota. So a 24 MB case can be refused because an animation run three weeks ago left 3 GB of frames next door -- measured 2026-09-08 at 30.8 GB used, of which 24.5 GB was regenerable scratch nothing was responsible for clearing. `report` ranks every directory by size and says how much of each could be produced again. `prune` removes only that -- `processor*`, solution times other than the latest, `VTK/`, animation frames -- and never `0/`, `constant/`, `system/`, `log.*`, `postProcessing/`, figures, reports or `Allrun`/`Allmesh`/`build.py`, and never the `polyMesh` inside a time directory, which on a moving mesh is the only record the run keeps of its own motion -- on such a time the fields beside that mesh are still offered one by one, because keeping the whole directory freed nothing at all on the moving-mesh case that most needs the space. It is a dry run unless `--apply`, it refuses to guess which study to prune, and it never deletes a whole study: removing one is a person's decision and this exists to make that unnecessary. |
| `mesh_digest.py` | `checkMesh` output as a metric table — the numbers and the patch table, no thresholds applied. |
| `cells_estimate.py` | Cell count predicted from the STL and the snappy dictionaries, before the build rather than after it. |
| `log_digest.py` | Solver log to a residual plot, a last-iteration table, and the continuity and bounding summary. Its first lines say how the run ended and what the residuals were doing when it did -- levelled off (a plateau; under a steady solver on an unsteady flow, the flow being reported), still falling, or climbing (a divergence) -- in words that depend on which, because only the last is a failure. |
| `reattach.py` | Where the flow leaves a wall and where it comes back, off the wall shear: the sign changes along a patch, with the primary reattachment picked out of them as the downstream end of the longest reversed-flow run -- not the first sign change, which on a backward-facing step is the corner eddy, and not the last, which is a secondary bubble. That rule is stated in the report wherever it actually chose between two bubbles, because on a geometry whose downstream separation is the longer one it names that instead. Both of those are printed beside the answer, so a number computed another way can be checked against the same list rather than merely disagreed with. Which sign of tau means attached is measured off `U` (tau tracks the near-wall velocity along a wall; the domain mean says which way downstream is), so no convention has to be known or got right. It reports the local face spacing with the number and rounds the answer to it. It never asserts a length unit it cannot read: with a `--height` other than 1 the answer is in step heights and says `h`; without one -- and `--height 1` is without one, since 1.0 is the flag's default and nothing here can tell an explicit 1 from an unused flag -- it is in whatever the wall's coordinate was and the label is left empty; `--units h` says it by hand, which is also the only way to label a table already sampled in x/h. A label invented here is a comparison switched off in `claims.py`. `--from-file` runs a sampled `.raw` or any two-column table through the same arithmetic; `--plot` draws the curve and the figure carries the number it was drawn from. |
| `reference_area.py` | How much of the body a mesh holds, and the area its forces divide by, read off `constant/polyMesh` whoever made it. A symmetry patch that crosses an open edge of the body patch cuts it, and each one that does makes the meshed part half of what it mirrors, so the areas in the file are 1/2 (1/4 for two planes) of the whole body's and the report says the factor with the plane and the points it was read from. Wetted and frontal areas are measured off the body patch as meshed -- frontal as the silhouette, rasterised -- so a half model's force over them is the whole body's coefficient with nothing to remember. Each plane doubles only what survives its mirror -- a force in the plane doubles, the component along the plane's normal cancels, and a moment is the other way about -- so on a hull cut at y = 0 the drag doubles while the half model's lift and pitching moment are zero on the whole body, and the factor for each of `forceCoeffs`' three directions is printed with the reason. A plane the body merely rests on cuts nothing: the test is whether the plane crosses an open edge of the body, not whether it shares points, because a car's four tyre patches on a slip floor share points right across the wheelbase. `--cd X --re R` holds a total drag coefficient against flat-plate friction (ITTC-57 turbulent, Blasius laminar), which friction alone sits under on any area no larger than the wetted one, and exits 1 when it is below -- a reason to check the area rather than an impossibility, since ITTC-57 is a correlation line: R01 delivered the SUBOFF hull's Ct as 0.00158 -- a half model's 43.74 N over the whole hull -- beside its own ITTC figure of 0.002907. A double-body waterline, where the plane closes a hull rather than mirroring it, is the one cut the mesh cannot tell apart, and `--not-mirror` says it. `results.py` runs the same readings on every force series it reports and `case_gen.py` writes `Aref` from them. Ascii meshes only, like `layer_report.py`, whose reader it uses. |
| `claims.py` | The number a figure was drawn from, stamped into the PNG itself, so the picture and the prose can be put side by side. `attach` stamps a figure -- including one a hand-written script drew -- `read` prints what one carries, and `check` reports two claims about the same quantity that disagree, and any claim the written answer contradicts or never quotes. It exists because a study delivered a figure annotated 7.57 with an answer that said 6.4 and reconciled neither; the caption drawn on a figure and the value stamped into it come from one call, so those two at least cannot drift. It exits non-zero on a disagreement -- as `preflight.py` does on a failing finding, and unlike the scripts here that only ever report -- because what it reports is arithmetic rather than judgement. Two claims whose unit labels differ are not compared, since guessing a conversion is how a reconciliation tool starts inventing its own errors, and they are printed as not compared rather than skipped: the all-clear is never shown over a pair nothing checked. |
| `render.py` | Fixed pyvista scenes for a case: mesh cuts and field slices, as PNGs, with cameras that do not move between runs so two of them are a visual diff. `--fields` takes solver outputs and also `vorticity` (signed, out-of-plane) and `Q`, which it computes from `U` rather than leaving to a hand-written script. `--contours N` draws N iso-contour lines over a slice, at levels taken from the field's own range with the two ends left off -- a level sitting exactly on the minimum is a single point and draws nothing, so asking for 10 lines used to be a way to get 8. `--diff OTHER` cashes the fixed camera in: one field of two runs as two panels on **one** colour scale and one camera, plus their difference on a diverging map centred on zero, with those numbers written beside the PNGs in a JSON sidecar rather than only claimed -- two panels each scaled to their own range are not a comparison. Both panels are at one instant -- the latest time the two runs share, printed rather than assumed, or whatever `--time` asks for -- and that time is on the labels, in the file names and in the sidecar, because each run opened at its own latest time reported 7.296e-4 on a pair whose real difference at the time they share is 6.790e-5, 10.7x out, and silently ran a different correspondence path as well. The second run is cut on the *first* one's plane; two meshes of the same domain are differenced by resampling one onto the other, and two runs whose bounds are more than 1% of the extent apart, or where the resampling covers under 99.9% of the cut, are refused by name instead of drawn, a difference between two different domains being a plausible picture of nothing. |
| `case_gen.py` | The case files for a mesh that already exists: `0/`, `system/` and `constant/`, sized to the mesh in front of it. It reads the patch names and types out of `constant/polyMesh/boundary`, the cell count, bounding box and smallest cell out of `checkMesh`, and each patch's area, centre and normal out of `mesh_look.py` -- and from those works out which way the inlet flows (its own normal, pointed at the middle of the domain, which is why a U-duct with both ends on the left comes out right), the hydraulic diameter the Reynolds number is on, and whether this is a body in open flow or a passage (a wall patch that is not part of the domain's own bounding box is a body), which sets the free-stream turbulence. Every patch gets a role -- inlet, outlet, wall, slip, symmetry, a belt that moves with the stream, a wheel that spins, empty -- from what you name, then from the mesh's own constraint types, then from the name; and a `boundaryField` entry in every field the turbulence model reads. Give it `--reynolds` and it solves for the viscosity and says so. It builds no geometry: that is the `cad` tool's job. An LES or a DNS is the same `pimpleFoam` run with a different `constant/turbulenceProperties`, so `--turbulence WALE` (or `kEqn`, `dynamicKEqn`, `Smagorinsky`, `sigma`, the Spalart-Allmaras and kOmegaSST DES hybrids -- the names ESI v2512 registers) writes the `LES` block with its subgrid model, its `delta` and that delta's coefficients, and changes everything around it that the switch actually costs: the convective scheme to the near-central `Gauss LUST grad(U)` and the ddt to `CrankNicolson 0.9`, because upwind dissipation acts at the grid scale the subgrid model acts at and is larger, so an upwinded LES is a slower RAS -- and it says it changed them and what from. A DNS gets the same arithmetic the case file's own comment carries -- eta = L Re^(-3/4), so Re^(9/4) cells for a resolved box of side L -- as a ratio against the mesh in hand, and the step count the run is beside the step it takes. `--study steady` with one is refused by name, there being no such thing, and on a one-cell-thick mesh it says what it has written: d/dz = 0 between two `empty` faces leaves no cascade for a subgrid model to be a subgrid to, so the case is a 2D laminar run carrying an extra viscosity. `--les-delta vanDriest` is the near-wall filter width (`cubeRootVol` keeps making nu_t through the viscous sublayer; an IDDES model refuses anything but `IDDESDelta` and so does this). `fieldAverage` is written with a stated `timeStart`, since the answer is a mean and a mean that starts inside the start-up transient is the transient diluted -- `spectra.py` decides where settled is. What it cannot know is the mesh, and what it prints instead is what the mesh it was handed implies: the first-cell height per wall measured through `layer_report.py` and the a priori y+ that follows, against the y+ ~ 1 a wall-resolved run wants and the log-layer cell a wall-modelled one wants, with `wall.py` named as the measurement once there is a solution; and the Courant-limited step from the smallest cell and the speed, which is the `maxCo` in the dictionary rather than a number nobody checked. `--tracer smoke --source vent` carries a passive scalar as well: OpenFOAM's own `scalarTransport` function object plus the four things it needs and a run stops or lies without -- the field, a `div(phi,smoke)` scheme under a `default none`, a linear solver named for the field, and a patch it comes out of (an `empty` or a `symmetry` one is refused, since a `fixedValue` on either does not start). The field is dimensionless, so what comes out is a fraction of the source value and a real concentration is one multiplication afterwards, exactly, because the equation is linear in it; there is no buoyancy in it, so a hot plume's rise is absent rather than approximated. `--schmidt 0.7` becomes `alphaDt 1.42857`, which is where the turbulent Schmidt number lives: `scalarTransport::D()` returns `alphaD*nu + alphaDt*nut` on the incompressible branch, and without the flag OpenFOAM's own Sc_t = 1 stands rather than a value this repository could not check. |
| `parametric.py` | One candidate of a parametric study, one point per call: `parametric.py CANDIDATE_DIR --round ROUND_DIR --lock goal.lock.json --mode mesh\|solve`. The caller writes `CANDIDATE_DIR/design_constants.py` (lines of `NAME = <number>`); the round's `build.py` begins with `from design_constants import *` and is refused if it does not, because a build that ignores the constants would score every candidate on the same geometry. It copies `build.py` and `hooks.py` in, runs the build, measures the mesh with `mesh_look.py` and `checkMesh`, and in `--mode solve` dresses with `case_gen.py <lock.case_gen_args> <hooks.case_args()> --iterations <fidelity.iters> --yplus`, solves with the lock's solver (`simpleFoam` unless said; `decomposePar`/`mpirun -np <fidelity.ranks>`/`reconstructPar` above one rank) into `log.<solver>`, then calls `score.py`. `hooks.py` may define only `case_args()` -- a hook that computes a metric is a second scorer -- and may not repeat a flag the lock sets, since the lock is the harness's physics. With `trim` in the lock (`{"variable": "ALPHA_DEG", "metric": "Cl", "target": 0.8, "tol": 0.01, "max_solves": 3}`) it solves at fixed lift: a secant over the design constant, each iteration its own rebuild in `trim_k/`, the accepted case's metrics reported with `trim: {variable, target, achieved, value, solves}`. `run.json` beside the candidate records what it decided as it goes, so a run killed for time can still be scored. |
| `score.py` | The **sole writer** of a candidate's `metrics.json`: `score.py CASE_DIR --lock goal.lock.json --out metrics.json [--mesh-only] [--label timeout --detail ...]`. It runs last, reads the case and the lock and nothing a hook left behind, and writes one shape for every point of a study: a `label` (`ok`, `mesh`, `diverged`, `timeout`, `unconverged`, `yplus`, `cells` -- the first that applies, in that order, and `timeout` only from the caller that killed the run), the coefficients as the mean over the last `fidelity.window` fraction of the `forceCoeffs.dat` rows (default 20%; never a point read, and `window` says how many rows), `converged` from `log_digest.residual_shape` (levelled or falling), `diverged` from a FOAM FATAL, a climbing residual, or a field held at its bound for most of the run, `yplus` min and max off the `yPlus` function object's last write against `fidelity.yplus`, the cell count off `constant/polyMesh/owner` against `fidelity.cells`, the `build.py` hash, the `case_gen.py` arguments used, the wall time, and the versions (`WM_PROJECT_VERSION`, gmsh, build123d). The keys are a contract and stay. |
| `compressible.py` | The same job for a compressible run: `0/`, `system/` and `constant/` for a transonic or supersonic case on a mesh that already exists. `p` is absolute static pressure in pascals and `T` is a field, which is the whole difference -- an incompressible `p` is p/rho in m2/s2 and a force taken off a compressible one as if it were kinematic is out by rho in both directions. `constant/thermophysicalProperties` takes the place of `transportProperties`: `hePsiThermo`, `perfectGas`, Sutherland transport and one specie's numbers, each printed with its source, and the molar mass and Cp are read back out of the file to give the gamma, the speed of sound, the Mach number, the density, the viscosity and the stagnation conditions it reports -- so there is no nu anywhere and the Reynolds number is an output. The boundary conditions come from the Mach number and the choice is stated: a subsonic outlet gets `waveTransmissive` rather than a `fixedValue` that reflects an arriving shock, a supersonic one gets nothing imposed at all, and `transonic yes` in `fvSolution` follows the same number. `forceCoeffs` is written with `rho rho` and the density field, which is the branch `preflight.py` already judges a compressible case by, and `Aref` on a 3D case is asked for rather than guessed. It reuses `case_gen.py`'s mesh reading and patch roles rather than repeating them, says which of `rhoSimpleFoam`, `rhoCentralFoam` and HiSA is actually on this machine instead of assuming, and for HiSA writes everything except the two scheme files -- those are HiSA's own and the authority for them is the ONERA M6 case in the image, so it prints the `cp` commands and what the files carry rather than inventing a dictionary that parses. |
| `preflight.py` | The cheap questions asked before an expensive run -- patch names against the fields, `empty` treatment on a 2D case, STL scale, Re against nu, predicted cells, checkMesh, a one-iteration probe, Courant and disk -- each answered as a finding with what was measured, what it means, and a repair you may or may not want. |
| `ladder.py` | A ladder of reduced cases for this case, read out of the case itself: the class it appears to be and the evidence for that reading, then the rungs in order -- what each one adds, what to measure on it, the answer that is already known and where it comes from, what counts as passing, and what it costs. The rule is that a rung's answer never comes from another solve: Archimedes, the ITTC-57 line, Kelvin's 19.47 degrees, Hagen-Poiseuille, the divergence theorem. `--rung n` prints one in full with the dictionary edits that would build it. `--record n --status pass\|fail\|skipped --value X` writes a rung's outcome to the study manifest on the volume, where the report's evidence column and `progress_report.py` read it back -- in this session or the next. It edits no case and runs nothing, the exit code is always 0, and climbing none of the rungs is a legitimate choice. |
| `advise.py` | Which solver and how many ranks, both read out of the case. `ladder.py`'s `classify` says which family it is, and the candidates for that family are listed with what each one is, the condition that makes it the one, and whether it is actually on `$PATH` here -- a name this script has wrong reports itself as not found rather than becoming a claim about the image. The compressible three come from `compressible.py` and the pick at a given `--mach` is `choose_solver`'s, so the two cannot drift; with no Mach number given, none is marked, because a Mach number is not in a case's files. For the rank count: cells from the built mesh or else from `cells_estimate.py`, cells per rank at each count up to the cores there are, and then this case's own solver logs -- split per run, since a restarted case leaves two or three in one file -- as a median s/iteration per rank count. Run at one rank count, it says so and reports no speedup; of 103 case directories in the studies behind this, one had been run at more than one. Then the machine, which is the other half of the same question: cores read three ways (`os.cpu_count`, `os.sched_getaffinity`, and the cgroup CPU quota, which is the one `nproc` misses inside a container) and memory read with the standard library on Linux, macOS or Windows, each probe free to answer "not established" rather than a default. Against that, what this case costs: seconds an iteration and hours in total as a p10-to-p90 band per solver, measured over 101 solver run segments in 50 case directories, and memory per cell from the one run in the whole corpus whose resident size anybody measured -- so that line names the study and its two PIDs, promises no cell limit off one case, and where the case is larger than the memory that was read, prints the cell counts that would fit instead. |
| `grid.py` | The same quantity on two or more meshes, as a number with an error bar: the refinement ratio of each pair, the order of convergence the solver actually achieved, the Richardson-extrapolated value, Roache's Grid Convergence Index on the fine grid, and the band that falls out of it -- `Cd = 0.412 +/- 0.004` from discretisation, where the only error bar anywhere else in here is `reattach.py`'s half a face spacing. The arithmetic is checked in this repository against NASA Glenn's published worked example (p = 1.786170, 0.97130, GCI 0.103083%), because the four lines of Richardson extrapolation are easy to write and easy to write wrongly, and the ways they mislead are silent. Four of them are handled rather than presumed away: two different refinement ratios, which the textbook single-`r` formula turns into a 20% error in the exponent everything else hangs off, so `p` is solved for out of Celik's relation by bisection (scipy is not on the image) and the equal-ratio case is then the same path rather than a special one; oscillatory convergence, where the middle value is not between the other two and the extrapolation would be arithmetic on a premise the data has already contradicted, reported as oscillatory with the interval the ladder does support and no GCI percentage at all; two grids agreeing to the last digit, which is mesh independence reached and not an order of convergence, so nothing is divided by the difference that is not there; and an observed `p` of -2.3 or 8, printed because it is the most diagnostic thing the triplet has to say and then not used, with the GCI falling back to the scheme's formal order and the clamp named in the output. The safety factor sits beside the band -- 1.25 over three grids with an observed `p`, 3.0 over two with an assumed one, and the report says which is the default -- since a band whose factor is unstated is a band of unstated size. Cell counts become a representative spacing through `N**(-1/3)` or `N**(-1/2)` from `--dim`, or from the mesh's own `empty` patches with that route named, because a plane case here is a one-cell-thick 3D mesh and its cell count cannot say which it is. The counts come from `checkMesh` through `mesh_digest.py`, or, where a rung has no checkMesh log, from the `nCells` note in its own `constant/polyMesh/owner` -- only logs were read before, and a rung whose count was in that file one directory away was dropped to stderr with a `continue`, turning a real three-grid ladder into a two-grid estimate on the wrong grid with a band 2.1x too wide and refusing a second real ladder outright. A rung that is still unreadable is named in the report, which is the artifact that gets saved, and the estimate made without it says it is DEGRADED. The quantities come from `postProcessing/*.dat` through `results.py`, a restarted series stitched back into one history, and every number in the report is printed beside the case, the file and the column it came from, a ladder being the one place where the wrong column on one of three cases gives a plausible answer. `--json` writes the same facts, and `--png` draws value against `h` with the extrapolation as the asymptote it is. |
| `lbm.py` | A lattice Boltzmann solver, D2Q9 with two relaxation times, in numpy and nothing compiled -- the first solver in this repository that is not an OpenFOAM application. Its subject is geometry that is a solid mask rather than a mesh: a boolean array streams and bounces with no snappyHexMesh, no checkMesh and no cell quality to argue about, which removes the stage this corpus loses the most time in. Two relaxation times rather than one because the free rate is spent fixing `(tau_plus - 1/2)(tau_minus - 1/2) = 3/16`, which puts a straight no-slip wall on the lattice link midpoint at any viscosity; a force-driven channel then reproduces the exact parabola to the convergence residual rather than to second order. That is held by measurement rather than by citation -- `benchmarks/lbm/` grades it at three viscosities and grades the contrast beside it, since `--relaxation bgk` must be exact at one viscosity and wrong either side of it -- and `benchmarks/lbm/README.md` says why: the obvious reference for the result does not state it in its abstract, and the paper that names it could not be read. Guo forcing with its odd and even parts given the odd and even rates, halfway bounce-back held on the solid nodes, a moving wall through the Ladd term. `poiseuille` and `cavity` are built in, it prints its own rate in million lattice updates per second, and `--out` draws the field beside the profile. What it is not: explicit, weakly compressible, second order, no turbulence model, the whole lattice in memory. `benchmarks/lbm/` is what it measured against the closed form and against Ghia, Ghia & Shin (1982). |
| `sph.py` | A smoothed-particle hydrodynamics solver, 2D and weakly compressible, in numpy and nothing compiled. Its subject is a free surface that breaks, folds or separates -- a collapsing column, a slosh, a wave impact -- where there is no mesh to deform because there are no cells. Wendland C2 kernel, density by the continuity equation rather than by summation (a summation density reads low at a free surface, which is where these cases live), Tait's equation of state, Monaghan's artificial viscosity on approach only, dynamic boundary particles, and symplectic velocity-then-position stepping because one of the graded cases is an oscillation and the other Euler pumps energy into it. The neighbour search is a uniform grid gathered into one dense `(particles, candidates)` index table, so every force is a masked sum along one axis rather than a Python loop over pairs. `hydrostatic`, `sloshing` and `dambreak` are built in. The cost is acoustic and not physical: `dt = 0.2 h / c0` with `c0` ten to twenty times the fastest flow, so a tenth of a second is thousands of steps however few particles there are, and halving `--dx` costs about eight times as much. `interFoam` and the `free_surface.py` template remain the better tools for the same physics once a mesh exists. `benchmarks/sph/` has both what it was graded on and what it was not. |
| `locate.py` | Where a diverging run went wrong, measured off the case rather than argued: the last written fields with min, max, mean and the extremum's cell, coordinates, owning patch and distance to the domain boundary, ascii or binary mesh alike; the solver log read for the field whose residual or bounding warning degrades first and when, with the Courant tail; and `--compare <other-case>` running the same scan on a second mesh of the same problem, because a value that does not move when the mesh changes is set by the boundary specification, not the grid. It reports in preflight's measured/means/repair register, offers no mechanism -- location over explanation is its whole idea -- edits nothing, and exits 0 whatever it finds. |
| `hisa_env.py` | Where HiSA -- the implicit density-based shock-capturing solver -- is on this instance: baked into the image (newer images, no exports needed), built onto the volume (older images), or absent. Says present, absent, or present-with-unresolved-libraries; for a volume build prints the four export lines a shell needs and the `-x` forwarding `mpirun` needs; prints the path to the ONERA M6 case HiSA ships, which is the shortest route to a correct dictionary set. `--json` for reading it from another script. |
| `layer_report.py` | How much of a wall actually carries a prism layer, measured off the mesh rather than taken from the mesher: the first-cell height at every patch face, `2 \|C_face - C_owner\|`, computed from `points`, `faces` and `owner` so nothing has to have been written and no solver has to have run. Coverage is that height against a reference wall spacing -- the same wall meshed with no layer request (`--ref`), or a spacing you already know (`--wall-spacing`); with neither, the threshold comes from the mesh itself and says so. It exists because snappyHexMesh reports a layer table, cfMesh reports nothing comparable, and the three claims about one hull could not be put next to each other until the meshes were measured with one metric. `--json` for reading it from another script. |
| `wall.py` | The y+ a run actually reached, read back off what it wrote, as against the y+ it was predicted to get. `case_gen.py` prints an a priori estimate from a flat-plate correlation before the solver starts -- on a generated aerofoil O-grid that estimate was y+ ~1200 under a wall function valid to 300 -- and `layer_report.py` measures the first-cell height, which is geometry and carries no velocity. This is the velocity field's own answer, per patch: min, max, mean, and the fractions of the wall sitting in the viscous sublayer, the buffer layer and the log layer, rather than one number for a wall that is never in one region. Anything that writes a PNG is worth knowing about twice over, because `read_file` on an
image path hands the picture back to you rather than its bytes — so a render is
something you can look at, not only something you can produce.

`ENVIRONMENT.md` lists what is installed on this instance — the Python packages, the
binaries on PATH, and which tool does a job (PDF is `pdftoppm`, not `fitz`; gifs are
`imageio`; meshing is `gmsh`) — so the environment can be read rather than probed, and the
sealed network is stated once rather than met as a surprise.

`templates/` holds the gmsh recipes as working scripts rather than as prose
to retype: `duct2d.py` for a plane case, `body_in_box.py` for a body in a flow box,
`free_surface.py` for a two-phase dam break, `rotating.py` for a frozen-rotor mixer,
`porous.py` for a Darcy-Forchheimer slab, `thermal_stress.py` for thermal
stress in a constrained bar, `viv_cylinder.py` for a cylinder on a spring, and
`evaluate_steady.py` for a round of a parametric study -- the last six write cases
meant to be solved rather than only meshed, and `evaluate_steady.py` takes its numbers
from a `design_constants.py` the caller writes beside it rather than from two numbers
edited at the top,
each copy-edit-run, each ending in `checkMesh` and a `mesh_look.py` call. They are kept
for whoever is working in bash. The CAD desk no longer copies and edits them — it works
a cell at a time in a kernel, and `templates/prep/` and `templates/snappy/` are the
pages it reads instead — but a recipe that runs is still the fastest way for a person,
or for the main agent, to get a plane case or a body in a box meshed without one.
What is known about each one's answer before its solver starts, and which two of them end
in an exact comparison, is written out case by case in the repository's tutorial index
rather than here: `benchmarks/tutorials/templates.md` in the distribution.

`notes/openfoam-field-notes.md` is OpenFOAM practice written as field notes rather than
procedure. `notes/free-surface-field-notes.md` is the same for two-phase VOF work, where
most of the ways a case is wrong leave a run that finishes and logs nothing: the
interface Courant limit, `p_rgh` against `p`, an open boundary that has to let flow back
in, why a uniform `alpha` start is not an initial condition, and how a smeared interface
and a resolved one differ in a picture. `notes/bundle-layout.md` is one suggested `/work` layout, labelled a
suggestion. `notes/openfoam-agent-architecture.md` is a longer design document, optional
reading.
